# Idea to Roadmap Example

Input:

```text
我想做一个给学生背单词的小程序。
```

Expected Layman-style output:

```text
原始需求 / Original request:
做一个给学生背单词的小程序。

风险判断 / Risk:
Medium. 想法清楚，但还没有目标用户、MVP 范围、数据结构和验收标准。

主要问题 / Issues:
- "学生" 范围太宽，需要先定义首版用户。
- 背单词功能容易膨胀到打卡、社交、AI 出题、排行榜。
- 还没有说明数据来源、复习方式和完成标准。

建议拆分 / Breakdown:
- 目标用户：初中或高中学生，先按一个年级词表使用。
- MVP 功能：词表导入、每日学习、认识/不认识标记、错词复习、学习进度。
- 暂不做：账号系统、社交、付费、复杂算法、教师后台。
- 数据结构草案：Word, StudySession, ReviewRecord。
- 页面草案：首页、学习页、错词页、进度页。

推荐先执行的任务 / First task:
先做只读项目规划，不写代码。

可复制给 Codex 的 prompt / Copyable prompt:
请先不要写代码。把"给学生背单词的小程序"拆成 v1 MVP：目标用户、核心场景、首版功能、暂不做功能、最小数据结构、页面草案、3 个开发阶段和第一阶段可执行 prompt。限制：不要设计账号、支付、社交或复杂推荐算法。

验收标准 / Acceptance criteria:
- 输出包含目标用户、MVP 功能、非目标、数据结构、页面草案和第一阶段 prompt。
- 第一阶段任务能在 15-45 分钟内开始执行。

停止条件 / Stop conditions:
如果需要选择具体平台、词库来源或登录方案，先列为待确认问题，不要继续扩展。

不建议现在做的事 / Not now:
不要直接生成完整小程序，不要接入支付或社交功能。

下一步 / Next step:
确认首版平台和目标学生群体，然后生成第一阶段实现任务。
```
