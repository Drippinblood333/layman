# Project Handoff Example

Input:

```text
我刚下载了一个项目，不知道怎么开始。
```

Expected Layman-style output:

```text
原始需求 / Original request:
用户下载了一个陌生项目，需要知道如何开始。

风险判断 / Risk:
Medium. 这是理解型任务，但如果没有边界，agent 可能全仓库逐文件解释或直接修改代码。

主要问题 / Issues:
- 需要先识别技术栈、入口和命令。
- 需要避免一上来修 bug 或重构。
- 需要产出下一步小任务，而不是长篇项目百科。

建议拆分 / Breakdown:
1. 只读理解项目结构。
2. 找启动、测试、构建命令。
3. 判断文档是否足够。
4. 推荐第一个 15-45 分钟小任务。

推荐先执行的任务 / First task:
只读项目接手分析。

可复制给 Codex 的 prompt / Copyable prompt:
请只读分析这个项目，不要修改文件。输出项目类型和主要技术栈、入口文件、核心目录、配置文件、包管理器、启动命令、测试命令、构建命令、README 是否足够，以及第一个 15-45 分钟内可完成的小任务。不要全仓库逐文件解释，不要修复问题，不要格式化代码。

验收标准 / Acceptance criteria:
- 能说明如何启动项目。
- 能列出核心目录和关键配置。
- 能给出一个小而明确的下一步任务。

停止条件 / Stop conditions:
如果缺少依赖、命令失败或文档不完整，只报告阻塞点，不要自行大改。

不建议现在做的事 / Not now:
不要直接升级依赖，不要清理全仓库，不要修复所有报错。

下一步 / Next step:
先运行只读接手分析，再决定是否处理启动阻塞。
```
