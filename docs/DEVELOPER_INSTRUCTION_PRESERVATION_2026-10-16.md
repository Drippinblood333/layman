# 保留用户开发指令（2026-10-16）

已修复明确的约束丢失问题：原先每次执行都传入 Layman 自己的 `-c developer_instructions=...`，这会覆盖用户配置中的同名字段，而不是追加说明。该改动优先保证原有约束，不据此宣称 token 节省。

## 复现与原生依据

[官方 CLI 配置规则](https://learn.chatgpt.com/docs/developer-commands#how-to-read-this-reference)说明单次命令行覆盖高于配置文件。用独立合成 Codex home 写入“保留公开 API、不修改无关文件”的固定哨兵，离线 `debug prompt-input` 显示：

| 情况 | 用户指令哨兵 | Layman 合约 | 原始任务 |
| --- | --- | --- | --- |
| 仅用户配置 | 存在 | 不存在 | 存在 |
| 原执行器的覆盖参数 | 消失 | 存在 | 存在 |
| 修复后的命令构建与原生渲染 | 存在 | 不再强加 | 存在 |

真实用户配置的前后 SHA-256 一致。整个复现和修复后验证不调用模型，不保存原始配置/渲染正文。

## 修复方式

使用官方 [app-server `config/read`](https://learn.chatgpt.com/docs/app-server) 按当前工作目录解析配置层级，避免另写 TOML 层级解析器。只向执行器返回“存在 / 明确为空 / 未知”三态，不返回或拼接用户指令。

- 存在非空开发指令：不发送覆盖参数，由原生 Codex 保留配置。
- 明确返回 null 或空白字符串：仍使用原有 Layman 合约。
- 读取超时、RPC 错误、缺失字段、非法字段类型或自定义 runner 无法查询：不把未知当成空，不覆盖；也不新增授权问题或停止任务。

执行结果新增固定分类 `developer_instructions_policy`：`preserve_configured`、`layman_guidance` 或 `preserve_unknown`。用户正文不进入命令参数、任务 stdin 的附加文本、结果或遥测；原始任务不改写。

查询等待原生初始化和对应响应；不能仅写入请求后关闭输入，再用零退出码推断配置为空。单行读取及队列大小有界，初始化/读取总等待默认三秒，结束关闭 stdin 并回收自建进程/线程，必要时使用现有受控进程树清理。清理另有有界等待，因此不宣称总耗时保证三秒内。该过程不写全局配置、不需要新依赖、不执行模型任务。

模型、ChatGPT 登录检查、原始请求、沙箱、工具/文件硬预算及交付检查均不变。`latency_ms` 现在包含新增配置探测及随后的文件快照，仍不代表前置登录/整体用户流程。

## 验证与边界

- 197 项相关 Plus-run、Plus-eval、CLI、token-benchmark 测试通过（18.88 秒）。覆盖三态、RPC 错误、未知字段、超时回收及三种命令策略；原始 stdin、权限和硬预算有断言。
- 原生私有 alpha.20 在有/无合成用户指令时分别返回 true/false。执行动作和登录检查仅在该合成验证驱动中替换为桩，**生产登录检查未绕过**；修复后的命令原生离线渲染仍含用户哨兵、无覆盖参数。配置读取原型约 70 毫秒，不代表所有机器的时延。
- Ruff、针对改动模块的 Bandit、保密扫描与 diff 检查通过。旧测试的“总会强加合约”断言改为验证未知时不覆盖，同时保留原生输出上限检查。
- 此处保护的是原生解析出的 `developer_instructions` 配置。不是对任意层级/内容的语义审计；没有给用户指令做缓存或加锁，探测与执行间的并发配置变动仍可能有竞态。
- 旧客户端或无法返回字段时采用不覆盖策略；这可能少掉 Layman 的可选文字提示，但不会关闭客户端硬限制或原生权限。未做真实任务质量或 token 收益比较，不把这次修复当模型策略优化。

私有复现、原生协议验证及固定布尔指标保留于忽略目录 `build/developer-instruction-precedence-2026-10-16/`。本批尚未托管 CI 验证、发布或替换安装，长期目标仍未完成。
