# 聚焦修错任务：较轻模型策略配对（2026-10-16）

结论：**不采用候选配置**。Luna/low 在这项任务上更快，但总 token 比当前 Sol/medium 多 10.68%，没有满足预先规定的至少减少 15% 条件。默认路由、模型配置和安装均未改变。

## 预先固定的实验

依据当前长期授权，助手另选两次订阅执行累计上限，已使用 2/2；不是用户逐字指定的次数，也不是内部推理请求数。启动前五小时额度已用 33%、周额度 21%。未使用付费 API、模型评委、重置券、安装替换或发布。

[官方模型说明](https://learn.chatgpt.com/docs/models#recommended-models)将 Luna 定位于聚焦、重复性任务，因此本批检验这个假设，而不是据文档直接降低默认档位。规划工具的一般路由建议不替代本试验清单中的实际配置断言。

使用一个新合成任务：修复 `first_duplicate(values)`，按遍历顺序返回最先第二次出现的值，支持 Python 相等语义及列表/字典元素，不修改输入，只允许修改 `src/target.py`。不是旧用例补跑，也不冒充正式发布留出集。

运行前，独立验收器已拒绝错误原实现、接受参考实现。每路检查 2,807 组输入：七种混合可哈希/不可哈希值组成的长度 0–4 列表共 2,801 组，加六组明确边界与顺序案例；检查返回值相等与输入未被修改。验收器未放入子工作区。它不证明任意对象行为、对象身份或函数签名的完整兼容性，也不是独立人工语义评分。

固定顺序为 Sol/medium→Luna/low。两路原始执行请求、夹具、balanced 执行合约、权限、上下文/输出/工具上限和压缩设置相同，仅在私有进程内改变模型与推理档位。这是两者组合的策略比较，不能分离模型或推理档位各自的因果效果。

执行源 HEAD 为 `add7401`；匹配私有 alpha.20 的 CLI、host、runner、setup 四个组件 SHA-256 与此前已验证运行环境一致。两路实际请求及执行合约哈希一致，完整实验摘要一致。预先 fsync 预留、互斥写入、每路只允许一次尝试、300 秒限制；首次任务/质量/用量/回退失败即停止，不替换或重放。实际均完成，无回退、用量完整。

## 决定与后续

较轻模型不能被直接当成更少 token。此配对总量增加 10.68%，输出 token 增加 29.32%，延时减少约 16.07%。预先规定的后续比较条件没有满足，故不修改生产模型或推理策略，也不追加同一任务以寻找正向结果。

一个顺序固定的合成配对不足以证明稳定因果、总体质量等价或代表性收益。不同模型、缓存、命令失败恢复和非确定性都可能影响结果。旧实验不合并、不重写。下一步应离线量化实际请求中工具定义等固定开销，而不是继续调整模型默认值。
