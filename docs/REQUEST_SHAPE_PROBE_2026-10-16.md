# 本机合成请求体诊断（2026-10-16）

本批定位了一个此前离线文本渲染没有量化的部分：CLI 将工具定义放入 `input` 的 `additional_tools` 项，而不一定放入顶层 `tools`。因此顶层工具数为零，**不代表工具定义没有占用请求体**。没有据此修改默认策略或宣称 token 节省。

## 方法与安全边界

按官方[自定义提供方认证](https://learn.chatgpt.com/docs/auth#alternative-model-providers)及[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，为单次 CLI 子进程设置独立随机提供方标识、回环 HTTP 地址、`requires_openai_auth=false`、合成环境变量凭证和关闭 WebSocket/请求重试。没有写入全局配置或替换已有登录。

服务只监听 `127.0.0.1` 随机端口；POST 必须是固定 Responses 路径且 Authorization 匹配合成凭证，否则拒绝。每次收到请求只统计字节数、类型、数量及 SHA-256；不记录正文、定义名称/描述、请求头或真实密钥。服务返回固定 SSE 文本，无模型推理、工具调用或上游模型请求。结束后关闭服务并等待线程退出。

使用私有 alpha.20 CLI 与合成 bugfix-03 任务，分别构建 Direct 和带当前 balanced 合约/输出设置的 Layman 请求。诊断期间两路强制只读，不能将其当成此前可写任务的真实执行重放。

共三次结构诊断：初始计数、识别输入项类型、补充定义数量及日志类别；每次两路各一次本机 POST，合计六次本机合成请求，零模型推理调用。三份独立计数快照保留，未将假响应中的零 usage 混入真实评测结果。下面只列最终快照。

## 限制与决定

- 本地合成提供方与真实 OpenAI/ChatGPT 认证、传输和能力协商不同，且使用只读权限。不能证明真实 Plus 会发送同一全集、所有 MCP 可用或某个优化将减少 34.27% token。
- 两路 stderr 均有警告/错误/回退及凭证相关标记，模块涉及 `shell_snapshot`、`auth_storage` 和 `skills::interface`；只记录类别，未保存原始日志或逐项确认根因。零退出码不代表启动无错误，更不代表用户工具已全部加载。
- 全局 config.toml 的前后 SHA-256 一致。CLI 正常启动可能更新缓存，本批不宣称系统完全零写入。所测本地提供方仅收到合成凭证；未审计 CLI 启动过程所有其他凭证读取。
- 根据实际观察到的命名空间结构，强化已有 API 代理回归夹具：`additional_tools` 内嵌命名空间及函数必须原样保留顺序和字段。该单项模拟检查通过，Ruff 通过；未增加测试数量、生产优化器或开关。
- 后续效率假设必须同时考虑内嵌工具定义与普通消息；不能只分析顶层 tools，也不能通过移除 additional_tools 制造表面缩短。已有官方延迟工具发现的兼容性检查不等于 Plus 默认可安全启用。

私有脚本与三份固定计数位于忽略目录 `build/request-shape-2026-10-16/`。生产代码、全局设置、安装、默认路由、依赖和发布保持不变；没有重跑不受影响的产品全套测试或平台构建。整体收益与公开发布门禁仍未关闭。
